# 中医药精准诊疗与科研一体化平台 — 产品前端设计交接说明

> 文档版本：1.0  
> 关联规划：`public/tcm-tech-plan.html`（技术架构 V2.1，**本文件不替代该文档**）  
> 适用范围：**面向医生与科研人员的产品前端**（非内部技术方案页）

---

## 1. 产品与命名方向

### 1.1 定位对齐（来自规划）

- **垂直病种**：现阶段聚焦**特应性皮炎**，不做全病种泛化。  
- **方法论**：**肠-脑-皮肤轴**中西医结合路径；贯通「临床—科研—转化」。  
- **能力组合**：中英文文献检索与 RAG、网络药理学分析（异步长任务）、TCM 知识图谱与生物网络可视化（AntV G6）、后续阶段辨证辅助 / 菌群 / 科研数据管理。  
- **边界**：**不替代医生诊断**；**不做普通患者 C 端**；AI 输出需可归因、可复核、带免责声明。

### 1.2 命名方向（可选，最终名可调整）

| 方向 | 主标题示例 | 副标题示例（可选） |
|------|------------|-------------------|
| **A · 病种垂直 + 学术可信** | **皮络 · 特应性皮炎中西医科研工作台** | 文献 · 网络药理 · 图谱 — 辅助诊疗与科研 |
| **B · 一体化链路** | **衡肤科研云（AD 专版）** | 精准诊疗辅助与科研数据一体化（中医 × 现代组学） |

**推荐**：对外传播可用 **B** 偏「平台感」，对内与论文材料可用 **A** 突出垂直深度；二者可并存（品牌名 + 产品线副标）。

## 2. 目标用户与核心场景

### 2.1 目标用户

| 角色 | 诉求摘要 |
|------|-----------|
| **皮肤科 / 中医皮肤科医师** | 快速查阅中英文证据、辨证与方剂思路辅助（非诊断替代）、可导出结构化报告用于病历或科室讨论。 |
| **研究生 / 科研助理** | 批量文献与上传 PDF、关键词与通路富集、网络构建与图表用于课题与论文附图。 |
| **院所 PI / 方法学合作者** | 关心数据来源、方法可重复性、合规与多中心扩展（后期）。 |

### 2.2 典型场景（需前端支持的交互叙事）

1. **证据检索**：中英文切换、复合检索（疾病 + 中医证候/方药 + 通路关键词）、结果列表 → 片段高亮 → 原文/PDF。  
2. **长任务分析**：提交网络药理学分析 → 展示 `task_id` 与进度 → 完成后查看报告与图表；失败可重试与限流提示。  
3. **图谱探索**：中药-成分-靶点-疾病链浏览、缩放筛选、导出图片（阶段目标）。  
4. **合规心智**：每次 AI 辅助结论旁常驻「辅助参考」「需医师复核」；账户与数据使用协议入口清晰。

## 3. 信息架构（主导航 / 模块）

以下按 **V2.1 规划中的 MVP → 阶段 2** 能力排序，导航可折迭为「一级少、二级多」，避免顶级菜单超过 **6±1** 项。

| 一级模块 | 包含能力（摘要） | 与规划对应 |
|----------|------------------|------------|
| **工作台** | 个性化入口：最近任务、收藏文献、进行中的药分任务 | 统一心智起点 |
| **文献与问答** | 双语检索、RAG 问答、上传 PDF、引用片段 | Embedding 分流、PDF 管道 |
| **网络药理学** | 提交分析、任务队列/轮询、报告阅读与导出（付费点） | Celery 异步、Claude 报告 |
| **知识图谱** | Neo4j 查询结果页、G6 网络交互、图例与筛选 | G6、图谱数据 |
| **科研数据**（阶段 2 加重） | 项目/数据集、脱敏病例与菌群等元数据、协作占位 | 路线图阶段 2 |
| **诊疗辅助**（阶段 2 加重） | 辨证辅助界面、证据链展示；强免责声明 | 精准辨证辅助 |
| **账户与合规** | 登录（魔法链接/邀请）、用量与 Claude 配额提示、隐私与算法说明 | NextAuth、PIPL/诊疗合规 |

**不包含在产品主导航的内容**：内部 Flower、服务器监控等运维界面（独立部署或仅管理员 URL）。

## 4. 关键页面与站点结构建议

### 4.1 两种思路

| 思路 | 说明 | 适用 |
|------|------|------|
| **单页营销 + 独立应用子域/路径** | 官网首屏价值陈述 → CTA「申请内测/登录」→ `/app` 进入 Ant Design 工作台 | 品牌传播与 SEO、对内测邀请友好 |
| **纯多页应用** | 登录后即全部在应用内，弱化对外营销页 | 极简上线、开发量略低 |

**推荐**：**单页营销（轻量） + 多页应用 `/app/*`**。规划已含 Next.js SSR/SEO，首页可静态生成要点；重度交互集中在应用壳（侧边栏 + 顶栏 + 内容区），与内部 `tcm-tech-plan.html` 的深色技术风刻意区分——**产品面向医务与科研人员，应采用明亮中性或柔和医学色调**，避免「内部运维仪表盘」观感。

### 4.2 关键页面 / 区块清单（MVP 优先级）

1. **营销首页**：病种聚焦、三联价值（文献 / 药理 / 图谱）、合规一句话、内测申请与登录。  
2. **登录 / 邀请**：魔法链接流程状态（邮件已发送 / 过期 / 白名单）。  
3. **应用壳**：左侧导航 + 顶栏（环境标识、语言、用户菜单、用量提示）。  
4. **文献检索页**：搜索框、中英切换、筛选侧栏、结果列表、详情抽屉（PDF 预览占位）。  
5. **RAG 对话区**：对话线程 + 引用卡片（来源标题、页码/段落、置信度可选）。  
6. **网络药理学**：表单参数 → 提交成功 → 进度条/步骤条 → 报告页（章节锚点、导出按钮）。  
7. **图谱页**：工具栏（搜索节点、布局切换）、画布区、右侧属性面板。  
8. **设置 / 合规**：隐私政策、用户协议、AI 使用说明、联系方式。

## 5. 视觉与品牌方向

### 5.1 色彩

- **主色**：建议 **青黛绿 / 竹青**（偏冷、低饱和，如 `#0d9488` ~ `#14b8a6` 区间）或 **墨蓝 + 玉色点缀**，传达「中医草木」与「现代医学」的平衡，**避免大红大绿高对比民俗配色**，除非节日运营专题另有规范。  
- **中性色**：白/浅灰背景（`#f8fafc`）、边框 `#e2e8f0`、正文 `#1e293b`、次要 `#64748b`。  
- **语义色**：成功/警告/错误沿用 Ant Design token，**医疗警示**用琥珀色强调「需人工复核」，而非仅用红色轰炸。  
- **深色模式**：可选第二阶段；若做，避免纯黑，用深蓝灰表面（与内部技术页区分——内部页可走深色，产品默认建议浅色护眼）。

### 5.2 字体

- **中文**：「思源黑体 / Noto Sans SC」为主，标题可加「思源宋体」少量点缀文书感（不宜全文宋体）。  
- **英文与数字**：系统 UI 堆栈 `system-ui` 或 Inter，表格数字可选 `tabular-nums` 对齐。  
- **代码/标识符**：等宽字体用于 `task_id`、基因名等。

### 5.3 情绪板（文字描述）

> 清晨诊室的自然光、古籍索引卡片与现代实验室记录并置；显微镜下的秩序感与水墨留白；**可信、安静、专业**，而非喧嚣促销或玄学符号堆砌。

### 5.4 与「中医 + 科研」可信感一致的图形策略

- 插画：**线性医学图示**（皮肤分层、肠脑轴示意）优于卡通人物。  
- 图标：Ant Design Icons + 少量自定义（草药叶子简化几何形，避免写实堆砌）。  
- 数据图：优先 **清晰轴标签与单位**、配色克制；导出论文级 PNG/SVG 为阶段目标。

## 6. 关键界面线框级说明

### 6.1 营销首屏（落地页）

- **顶栏**：Logo、产品短名、「功能」「合规」「申请内测」「登录」。  
- **首屏三栏或左文右图**：主标题 + 副标题 + 双 CTA（登录 / 了解合规）；右侧 **单一主视觉**（肠-脑-皮肤轴信息图线稿）。  
- **下方折叠**：证据链模块图标三枚（文献 / 网络药理 / 图谱）+ 单段合规声明。

### 6.2 应用核心工作区（默认布局）

- **左侧**：可收起导航（图标 + 文字），当前模块高亮。  
- **顶栏**：面包屑（深度 >2 级时）、全局搜索入口（可选）、用户与用量。  
- **内容区**：最大宽度容器（如 `1200px`）居中，避免超宽屏上行过长；**数据表格**使用斑马纹与固定表头。  
- **右栏（可选）**：详情上下文、AI 引用列表、图谱属性——与中间主任务形成 **主从布局**。

### 6.3 列表 / 详情模式

- **列表页**：表格或卡片；支持保存检索条件；批量操作谨慎开放（医疗场景误操作成本高）。  
- **详情**：抽屉优先于整页跳转（保持检索上下文）；PDF 用侧栏预览 + 主区摘要。  
- **图谱**：全屏模式按钮（沉浸式探索），退出后保留筛选状态。

## 7. 组件与交互原则

### 7.1 与设计体系

- **Ant Design 5** 为基准（与规划一致），定制主题 token（主色、圆角略收紧 **6–8px** 体现专业感）。  
- **AntV G6** 图实例需独立容器与 **加载占位骨架**，避免空白闪烁。

### 7.2 可访问性

- 全页可键盘 Tab 顺序合理；图表关键信息有 **文本摘要或表格备选**。  
- 对比度满足 WCAG AA 为底线；表单关联 `label`。  
- AI 生成区域默认 **可复制纯文本**，便于医师粘贴至病历系统外编辑。

### 7.3 数据密集界面

- 长表格：**虚拟滚动**或分页；列显隐；导出 CSV（权限控制）。  
- 指标卡片：**单位与采样时间**同显，避免孤立数字。

### 7.4 空态 / 加载 / 错误

| 状态 | 原则 |
|------|------|
| **空态** | 说明「尚无数据」的原因与下一步（上传文献、发起检索示例）；避免俏皮文案，保持专业。 |
| **加载** | 超过 2s 显示进度或骨架屏；Celery 长任务必须 **进度 + 预计时间不确定时的诚实文案**。 |
| **错误** | 区分网络、权限、限流、配额用尽；**配额类**给明确数字与重置时间（呼应规划中的 Claude 日限额）。 |
| **重试** | 幂等操作提供重试；分析任务失败保留参数草稿。 |

### 7.5 合规相关界面元素（强制考虑）

- AI 输出区块页脚：**非诊断结论、需结合临床**。  
- 首次登录：勾选已阅读《用户协议》与《隐私政策》；涉及脱敏数据前 **二次确认**。  
- 对外演示环境：**水印或演示数据标识**。
