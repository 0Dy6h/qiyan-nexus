一、产品定位与边界

一句话定位

为特应性皮炎场景提供基于肠-脑-皮肤轴的中西医结合文献检索、网络药理学分析与诊疗辅助，打通临床—科研—转化。

核心优势（摘要）
  • 垂直病种深度 vs 通用中医 AI
  • 中西医结合背景与真实需求洞察
  • 现代数据（菌群、免疫）与证型关联能力
  • 临床与研究数据壁垒

绝对不做的边界

  • 不做全病种 — 现阶段只做特应性皮炎，做深做透
  • 不替代医生诊断 — 辅助决策与科研工具
  • 不做普通患者 C 端 — 先服务医生与科研人员
  • 不自训大模型 — 成熟 API + 开源模型
  • 不追求一次性完美 — MVP 上线后快速迭代

在 V2.1 中新增 PgBouncer、双语 Embedding、对象存储与监控层；流量经 HTTPS → Nginx 分流至 FastAPI（/api）与 Next.js 前端。

    │ HTTPS
    ▼
Nginx（SSL + 静态 + 限流）
    ├── /api/*  →  FastAPI :8000
    │       ├── 同步：文献检索、图谱查询
    │       ├── 异步：网络药理学 → Celery
    │       └── Redis：热点 + 语义缓存
    └── /*      →  Next.js :3000

数据层：PgBouncer → PostgreSQL+pgvector │ Neo4j Aura │ Redis │ R2/MinIO
AI 层：text2vec（中）│ PubMedBERT（英）│ DeepSeek API │ Claude API（配额）
监控：Flower :5555 │ Sentry

3.2–3.3 LLM 路由与语义缓存

任务类型模型说明
关键词提取DeepSeek-chat简单、低延迟
基础问答 / RAGDeepSeek-chat量大、成本敏感
中医证候分析Claude Sonnet复杂推理与高准确率
网络药理学报告Claude Sonnet通路机制与连贯论述
代码/脚本DeepSeek-chat成本低
批量摘要DeepSeek 批量 API量大优先成本
Claude 配额：约 50 名内测用户若每人每日多次复杂查询，token 消耗可能远超原 ¥200 预算。建议在 Redis 设置每用户每日 Claude 上限（文档建议约 10 次/天），并对相近语义问题做结果缓存复用。

语义缓存：同一语义重复提问时命中向量相似度阈值（如 0.92）则直接返回缓存，跳过 LLM，降低费用与延迟。

四、原方案代码问题与修复（摘要）

4.1 pgvector 写入

禁用将向量 str() 化写入；使用 pgvector.psycopg2.register_vector 并传入 numpy 数组，否则检索失效。

4.2 富集分析

用 gseapy enrichr 对接 GO/KEGG 等基因集，替代已关闭的 DAVID 公开 API。

4.3 Celery 异步

药分分析通过 /analyze 返回 task_id，/result/{id} 轮询状态，避免 HTTP 长时间阻塞。

五、医学专用 Embedding（双语）

P0 数据含大量中文文献；仅用英文 PubMedBERT 会拖累中文检索。双编码器按语言分流，均为 768 维，同表存储并以 language 字段区分。

模型类型场景成本
text2vec-base-chinese-paraphrase中文语义知网/万方、中医术语免费本地
PubMedBERT英文生物医学PubMed 文献免费本地
multilingual-e5-large 等备选维度/显存权衡见原文对比

七、基础设施模块（补全）

7.1 认证

MVP 推荐 NextAuth.js：邮件魔法链接 + 邀请白名单，零月费，与 Next.js 集成快。

7.2 PDF 管道

PyMuPDF 为主；文本过短时降级 unstructured；再必要时考虑 OCR 路线。

7.3 对象存储

Cloudflare R2 10GB 免费、S3 兼容；便于日后迁移 OSS。

7.4 图谱可视化

第 4 月可先用 Neo4j Bloom 验证；并行推进 AntV G6 产品化。

7.5 可观测性

MVP 最小集：Flower + Sentry 免费档 + BetterStack 可用性监控。

八、部署与资源（摘要）

内存：后端含双 Embedding 各约 420MB，合计约 2.6GB 量级服务占用，已逼近 2 核 4G 的舒适区。可考虑 Celery Worker 延迟加载 text2vec、容器内存限额、SWAP 或升级至 4 核 8G（约 ¥168–200/月）。

docker-compose 包含 postgres、pgbouncer、redis、backend、celery_worker、flower（建议仅本机暴露 :5555）、frontend、nginx。Nginx 对通用 API 与 Claude 相关路径分别限流（文档示例：30r/m 与 10r/m 等级）。

11.2 合规要点（摘要）

  • 互联网诊疗：禁止 AI 替代诊断；全程标注辅助科研工具与免责声明。
  • PIPL：临床数据需授权；脱敏病例亦建议签署数据使用协议。
  • 生成式 AI 办法：内测邀请制阶段风险可控；公开上线前预留算法备案周期（约 1–3 个月）。
