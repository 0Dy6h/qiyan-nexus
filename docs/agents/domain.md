# 领域文档

工程技能在探索代码库时如何消费本仓库的领域文档。

## 探索前先读这些

- **`CONTEXT.md`** — 仓库根目录的领域术语表（每次会话必加载）
- **`docs/adr/`** — 阅读与你即将工作的领域相关的架构决策记录

如果上述文件不存在，**静默继续**，不要报告缺失或建议创建。生产者技能（`grill-with-docs`）会在术语或决策实际需要记录时惰性创建。

## 文件结构

单一上下文仓库：

```
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-xxx.md
│   └── 0002-xxx.md
└── src/
```

## 使用术语表词汇

当你的输出涉及领域概念（问题标题、重构建议、假设、测试名称），请使用 `CONTEXT.md` 中定义的术语。不要使用术语表明确避免的同义词。

如果你需要的概念尚未在术语表中，这是一个信号——要么你在引入项目不使用的语言（重新考虑），要么确实存在缺口（标记给 `grill-with-docs`）。

## 标记 ADR 冲突

如果你的输出与已有 ADR 矛盾，请明确指出，而非静默覆盖：

> _与 ADR-0007（事件溯源订单模型）矛盾——但值得重新讨论，因为……_
