## 一、环境准备

### 1.1 访问地址
- **前端地址**：http://localhost:3000
- **后端地址**：http://127.0.0.1:8000
- **健康检查**：http://127.0.0.1:8000/health

### 1.2 访问控制（如适用）
- 本地浏览器走查默认使用 open dev mode；前端不会读取或携带后端 `X-Access-Token`
- `QIYAN_ACCESS_TOKENS` 仅供后端 middleware、curl 与自动化脚本直连验证，不能放进浏览器公开环境变量
- 云端 reviewer 通过 HTTPS + 每人独立的 nginx Basic Auth 账号访问；nginx 在服务端注入后端内部 token，并把 `$remote_user` 覆盖为 `X-Qiyan-Reviewer`，reviewer 不应获得内部 token，也不能自行选择 owner
- network task 已按 reviewer 隔离；不同账号读取同一 task id 应得到 404。PDF、解析结果与 uploaded PDF RAG chunk 仍是实例共享边界，只能使用所有参与者均有权查看的材料
- 云端账号由技术团队发放和撤销，具体边界见 `docs/guides/cloud-trial-deployment-runbook.md`

### 1.3 浏览器要求
- 推荐使用 Chrome、Edge 或 Firefox 最新版本
- 需启用 JavaScript
- 屏幕分辨率建议 ≥1280×720

### 1.4 评审前确认
- [ ] 前后端服务均已启动
- [ ] 可以访问前端首页（显示"青黛绿"主色调界面）
- [ ] 浏览器控制台无明显错误（F12 查看）
- [ ] 本轮使用默认离线 profile：deterministic provider、keyword retrieval、不开启真实 LLM、不启用访问 token
- [ ] 如走云端试用，确认 reviewer 使用个人 Basic Auth 账号，匿名访问返回 401，浏览器 bundle/请求中没有后端内部 token
- [ ] 如需上传 PDF，主样本使用 `local-review-pdfs/健脾养血祛风法治疗特应性皮炎临床疗效及对皮肤屏障功能的影响_杨雪松.pdf`
- [ ] 如需演示抽取质量警告路径，可追加 `local-review-pdfs/中医辨证治疗异位性皮炎临床观察_周海啸.pdf`

## 二、核心流程走查

### S1 文献四来源检索

#### 1.1 基础检索
- [ ] 访问 `/literature` 页面
- [ ] 在搜索框输入关键词（如"特应性皮炎"或"AD"）
- [ ] 点击"搜索文献"按钮
- [ ] **预期结果**：
  - 显示文献列表，每条包含标题、作者、年份、来源
  - 列表项可点击查看详情
  - 页面底部有分页控件（如有多页）

#### 1.2 数据来源切换
测试四种数据来源视图：

**a) 全部来源**
- [ ] 选择"全部来源"
- [ ] 执行搜索
- [ ] **预期结果**：返回所有来源的文献（seed literature + PubMed + 上传 PDF）

**b) PubMed 记录**
- [ ] 选择"PubMed 记录"
- [ ] 执行搜索
- [ ] **预期结果**：
  - 仅显示来源为 `pubmed` 的文献
  - 页面顶部显示合规 banner：`PubMed 记录（含演示 seed）`
  - 每条记录显示 `记录来源`，能区分 `演示样本` 与 `PubMed 实时同步`
  - banner 明示演示 seed 不可当作外部可检索真实文献

**c) CNKI 样本**
- [ ] 选择"CNKI sample"
- [ ] 执行搜索
- [ ] **预期结果**：
  - 仅显示来源为 `cn_literature` 的文献
  - 页面顶部显示合规 banner："数据来源：CNKI 中文文献样本数据"

**d) 上传 PDF**
- [ ] 选择"上传 PDF"
- [ ] 执行搜索
- [ ] **预期结果**：
  - 仅显示已挂载上传 PDF 的文献
  - 页面顶部显示合规 banner："数据来源：用户上传 PDF 文献"

#### 1.3 文献详情页
- [ ] 点击任一文献条目
- [ ] **预期结果**：
  - 跳转到 `/literature/[id]` 详情页
  - 显示完整的文献信息（标题、作者、期刊、年份、摘要、关键词）
  - 如有 PDF，显示 PDF 元数据（文件名、解析状态）
  - 如有 DOI/PMID，显示外部链接

### S3 RAG 答案 + 免责声明

#### 2.1 基础问答
- [ ] 访问 `/rag` 页面
- [ ] 在问题输入框输入医学问题（如"中医如何治疗特应性皮炎？"）
- [ ] 点击"提问"按钮
- [ ] **预期结果**：
  - 显示加载状态（loading indicator）
  - 返回答案文本
  - 显示引用文献列表（citation cards）
  - **必须**在答案末尾显示免责声明："非诊断结论、需结合临床。"

#### 2.2 引用验证
- [ ] 检查答案中的引用编号（如 [1], [2]）
- [ ] 对比引用列表中的文献
- [ ] 点击引用文献的标题
- [ ] **预期结果**：
  - 引用编号与文献列表一致
  - 点击后跳转到对应文献详情页
  - 文献详情页可正常加载

#### 2.3 Markdown 导出
- [ ] 在 RAG 答案页面底部找到"导出为 Markdown"按钮
- [ ] 点击导出按钮
- [ ] **预期结果**：
  - 浏览器下载 `.md` 文件（文件名格式：`qiyan-rag-answer-YYYYMMDD-HHmm.md`）
  - 打开文件，内容包含：
    - 问题
    - 答案
    - 引用文献列表
    - 免责声明
    - provider 信息、检索元数据

#### 2.4 错误处理
- [ ] 输入空问题，点击提问
- [ ] **预期结果**：显示错误提示，不发送请求

---

### S2 PDF 上传 → 解析 → RAG 引用

#### 3.1 PDF 上传
- [ ] 访问任一文献详情页（建议选择没有 PDF 的文献）
- [ ] 找到"上传 PDF"区域
- [ ] 选择本地 PDF 文件（建议使用文本型 PDF，≤10MB）
- [ ] 点击"上传"
- [ ] **预期结果**：
  - 显示上传进度
  - 上传成功后显示文件名
  - 上传成功后自动进入解析流程，按钮短暂显示"解析中..."

#### 3.2 自动解析确认
- [ ] 等待自动解析完成
- [ ] **预期结果**：
  - 状态变为 `parsed`，或在不可抽取时变为 `failed`
  - 如果解析成功，显示 `extraction_method`（如 `pypdf-text-preview`）
  - 文本预览优先展示摘要/正文窗口；如果 PDF 字体映射导致数字或表格乱码，仍显示抽取质量提示，需对照原文核对关键数值
  - 如果解析失败，显示 `failed` 及失败原因
  - 可在人工校正区域标记"已解析"或"解析失败"

#### 3.3 PDF 预览
- [ ] 如果解析成功且提供了预览文本
- [ ] 在详情页查看预览文本区域
- [ ] **预期结果**：
  - 显示 PDF 的文本内容片段
  - 文本可读、格式基本正确

#### 3.4 RAG 引用验证
- [ ] 返回 `/rag` 页面
- [ ] 提问与刚上传的 PDF 相关的问题
- [ ] 检查答案的引用列表
- [ ] **预期结果**：
  - 如果 RAG 引用了上传的 PDF，citation card 上会显示"来源：上传 PDF"标记
  - 点击该 citation 可跳转到对应文献详情页
  - 详情页显示上传的 PDF 元数据

### S4 网络药理学 mock 边界

#### 4.1 创建分析任务
- [ ] 访问 `/network` 页面
- [ ] 在"中药/复方名称"输入框输入名称（如"青黛"）
- [ ] 在"疾病名称"输入框输入"特应性皮炎"
- [ ] 点击"开始分析"按钮
- [ ] **预期结果**：
  - 显示加载状态
  - 返回任务 ID
  - 自动跳转到结果页面或显示结果区域

#### 4.2 网络图可视化
- [ ] 在结果区域查看网络图
- [ ] **预期结果**：
  - 显示 node-link 图（中药 → 化合物 → 靶点 → 通路 → 疾病）
  - 节点按层级排列
  - 边的粗细/透明度反映 score
  - 有图例说明节点类型

#### 4.3 图交互测试
**鼠标交互**
- [ ] 将鼠标悬停在某个节点上
- [ ] **预期结果**：节点高亮，相连的边高亮
- [ ] 移开鼠标，高亮消失

**键盘交互**
- [ ] 按 Tab 键进入图区域
- [ ] **预期结果**：第一个节点获得焦点（focus ring 可见）
- [ ] 按 Enter 或 Space 键
- [ ] **预期结果**：节点切换选中状态（pressed），相连边高亮
- [ ] 按 Escape 键
- [ ] **预期结果**：清除选中状态
- [ ] 按 ArrowDown 键
- [ ] **预期结果**：焦点移到同层下一个节点
- [ ] 按 ArrowRight 键
- [ ] **预期结果**：焦点跳到右侧相邻层的节点

#### 4.4 链（Chains）展示
- [ ] 在结果区域查看"作用链"列表
- [ ] **预期结果**：
  - 显示若干条 chain（如"青黛 → 靛玉红 → EGFR → MAPK 通路 → 特应性皮炎"）
  - 每条 chain 有评分（score）
  - 显示证据来源的文献引用

#### 4.5 富集分析
- [ ] 在结果区域查看"GO/KEGG 富集分析"表格
- [ ] **预期结果**：
  - 显示显著富集的通路/功能（最多 10 条）
  - 每条包含 Term ID、通路名称、类别、重叠基因数、P-value、基因列表
  - P-value < 0.05

#### 4.6 Markdown 报告导出
- [ ] 点击"导出网络分析报告"按钮
- [ ] **预期结果**：
  - 浏览器下载 `.md` 文件（文件名格式：`qiyan-network-{herb_name}-{disease}-YYYYMMDD-HHmm.md`）
  - 打开文件，内容包含：
    - 分析参数（中药、疾病）
    - 作用链列表
    - 富集分析表格
    - 免责声明

## 三、评审维度

### 3.1 医学准确性
- [ ] **免责声明**：所有 AI 生成内容是否都明确标注"非诊断结论、需结合临床"？
- [ ] **引用可追溯性**：RAG 答案的每个引用是否都能追溯到具体文献？
- [ ] **证据链透明性**：网络药理学的作用链是否显示证据来源？
- [ ] **数据来源说明**：文献检索是否清楚标注数据来源（PubMed、CNKI、上传 PDF）？

### 3.2 可用性
- [ ] **操作直观性**：是否能在无技术背景的情况下完成核心流程？
- [ ] **错误提示友好性**：输入错误或 API 失败时，是否有清晰的错误提示？
- [ ] **加载状态明确**：长时间操作（如 RAG 问答）是否有明确的加载指示？
- [ ] **导航一致性**：页面间跳转是否顺畅？返回操作是否符合预期？

### 3.3 性能
- [ ] **文献检索响应时间**：搜索是否在 1 秒内返回？
- [ ] **RAG 问答响应时间**：
  - deterministic provider：是否在 2 秒内返回？
  - 真实 LLM（如启用）：是否在可接受范围内（提示用户预期等待时间）？
- [ ] **页面加载速度**：首次访问各页面是否流畅？
- [ ] **图渲染性能**：网络图是否能流畅交互（无卡顿）？

### 3.4 合规性
- [ ] **数据来源透明**：是否清楚说明每类数据的来源？
- [ ] **用户边界明确**：是否清楚标注"仅医生/科研端，不面向患者"？
- [ ] **版权提示**：上传 PDF 流程是否有版权提示？
- [ ] **隐私说明**：是否有隐私政策说明（即使是 placeholder）？
