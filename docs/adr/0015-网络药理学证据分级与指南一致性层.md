# ADR-0015: 网络药理学证据分级与指南一致性层

日期：2026-07-04

## 状态

Accepted

## 背景

在一次对外定位路演（北京中医药大学「数智医研·融合未来」学术论坛）中，本平台对外宣称「内嵌《网络药理学评价方法指南》」「AI 预测驱动、定量药效排序」「多路径证据链可追溯」。用第一性原理核对仓库当前事实源（`docs/current-state.md`、`backend/app/services/network.py`、`backend/app/services/rag.py`）后确认：

- 「《网络药理学评价方法指南》」在整个仓库只在一份 review 文档里被提及一次，**代码与数据里没有任何对应实现**——是空头承诺。
- RAG citation 置信度是 `CONFIDENCE_BY_SOURCE_TYPE` **常量**（`backend/app/services/rag.py`），network chain 的 `score` 来自 seed edge，两者都**不是**「AI 预测的定量药效」；把它讲成「定量药效排序」会给不确定性套上假精度。
- network chain 已有 `target_evidence_type`（`mock` / `known_activity` / `predicted` / `mixed`），但它只描述「靶点」这一个节点，只在 live 报告表格里露出，**没有对整条 成分-靶点-通路-疾病 机制链给出统一的证据支持等级**，也没有与任何评价原则挂钩。

第一性原理判断：真正值得从那套宣称中借鉴的内核，是把「评价方法指南」落成一个**显式、确定性、可测**的证据分级层，而不是照抄「定量药效排序」这种当前无实现支撑、且会误导可信度的措辞。

《网络药理学评价方法指南》的三条公认原则——**可靠性、规范性、可解释性**——恰好与仓库已建成的三根脊柱对齐：

| 指南原则 | 仓库已有能力 |
|---|---|
| 可靠性（数据来源可追溯） | `data_mode`、`data_sources`、`record_origin`、live provenance |
| 规范性（流程可复现） | deterministic 默认、request id、`rag_sli`、参数留痕 |
| 可解释性（结论可核对） | citation 契约、grounding gate、Markdown/DOCX 报告导出 |

因此本层不新建脊柱，只补脊柱上缺的那一块：**给每条机制链一个确定性的证据支持等级，并在报告里显式说明分级依据**。

## 决策

1. **证据支持等级（`evidence_level`）落在 `NetworkChain` 上，四级有序标度**（从弱到强）：

   | level | 含义 | 触发条件 |
   |---|---|---|
   | `mock_inferred` | 演示/推断，无外部来源支撑 | `data_mode="mock"` 的任何链，一律最低级 |
   | `predicted` | 计算预测靶点 | live 且 `target_evidence_type="predicted"` |
   | `literature_supported` | 有文献/关系证据引用 | live 且 `target_evidence_type="mixed"`，或存在 `evidence_refs` |
   | `experimental` | 已知实验活性证据 | live 且 `target_evidence_type="known_activity"` |

2. **一条链的可信度由其最弱一环决定**：`evidence_level` 是**确定性纯函数**，仅由 `data_mode` + `target_evidence_type` + `evidence_refs` 推导，不引入随机、不调用外部服务、不做「定量药效」估计。

3. **强制不变量（诚实边界，测试锁定）**：
   - `data_mode="mock"` 的链**必须**是 `mock_inferred`，不得因任何字段升级——mock 不得伪装成有证据支撑的结论。
   - 分级只重排「支持强度」的表达，**不改变** chain `score` 排序，也不宣称概率/疗效。
   - 免责声明 `非诊断结论、需结合临床。` 在报告中保持 byte-identical。

4. **报告新增「证据分级」说明段**：`build_network_report_markdown` 增加一节，列出本次结果各证据等级的链数量与分级依据文字，明确「mock 结果整体为 `mock_inferred`，不代表指南意义上的可靠性达标」。为避免破坏被测试逐字锁定的链路表头，分级信息以**独立小节**呈现，不改动既有 mock/live 链路表头字符串。

5. **默认路径不变**：本层在默认 mock 路径下就生效（只是等级恒为 `mock_inferred`），不需要、也不默认启用真实 LLM / 真实数据库 / live 网络 provider。

## 后果

正面：
- 幻灯片吹得最大的「内嵌评价方法指南」从空头承诺变成真实、可测、确定性的分级层。
- 每条机制链带上可追溯的证据等级，强化「可靠性/规范性/可解释性」表达，且诚实标注 mock 边界。
- 零新增重依赖，纯确定性，完全走默认路径，符合内部预览护栏。

代价：
- 这是启发式分级，不是指南全量条目核验；后续若要做真正的指南符合性打分（如样本量、阳性对照、多重校正）需另开切片。
- live 路径下 `evidence_level` 的精度受 `target_evidence_type` 精度约束，换 connector 需复核映射。

## 验证

- 后端 `pytest`：新增 `test_network_evidence_level.py` 锁定 mock→`mock_inferred`、live 各 `target_evidence_type` 的映射、以及报告分级段存在；既有 `test_network_report_service.py` 全绿。
- 后端 `ruff format --check` / `ruff check` / `mypy app` 全绿。
- 前端 `pnpm test` / `pnpm typecheck` / `pnpm build` 全绿（`NetworkChain` 类型新增可选 `evidence_level`，向后兼容）。
