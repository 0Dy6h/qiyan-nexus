# ADR-0018：以组学策略为底层逻辑的网络药理学平台契约

- 状态：Accepted（Gate 1 已确认 2026-08-16）
- 日期：2026-08-15
- 决策者：项目所有者（研究者）
- 前序契约：ADR-0017（Accepted，继续有效）
- 取代：无

## 背景与动机

ADR-0017 已把 Qiyan Nexus 唯一产品主轴固定为“面向特应性皮炎中医药研究的窄领域网络药理学自动化科研辅助平台”，并把文献/PDF/RAG/引用/导出收敛为证据服务层。截至 2026-08-15，工程侧已具备研究协议门禁、双侧离线 raw-artifact provenance、owner-scoped 逐行人工 adjudication 与 source-bound 候选装配计划；但这些能力只证明“输入已封存、来源可追溯、可复算”，不证明靶点、通路或机制结论具有真实生物学证据。

当前事实必须诚实承认：

- 网络药理学默认仍是 mock 演示链路；live 链路是显式 opt-in 的多数据库预测链。
- 检索质量指标 `precision@5` / `MRR@5` 仍为 `null`，150 个 Track A 人工标签尚未填写。
- 人工 adjudication 与候选装配计划已有工程能力，但尚无任何真实领域 reviewer 判定记录；正式医生/科研 reviewer sign-off 仍未完成。
- `formal_network_ready` 仍为 `false`，不应以任何方式宣称科学就绪。

本质短板不是“工程 provenance 不够”，而是：**平台目前主要是数据库预测工具，缺真实测量数据验证**。即使把每一条数据库预测边都追溯清楚，它仍是“预测”，不能冒充“实验证据”。

研究者已被要求建立组学策略思维；研究者本人的夏枯草干预甲状腺疾病整合研究（古籍数据挖掘 → 网络药理学 → 分子对接 → 分子动力学，四步完整跑通、可复算）提供了一个可对照的完整研究路径。市面网络药理平台多数止步于数据库预测，真正差异点应是把“真实证据验证”放进地基，而不是在报告层面补一句免责声明。

因此需要一份方向性 ADR，把平台底层逻辑从“数据库预测工具”升级为“组学策略”，同时不推翻 ADR-0017 的当前产品契约。

## 决策

### 1. 组学策略作为底层逻辑

平台底层逻辑定义为：

> **组学策略（Omics Strategy）= 系统整体观：不预设单一靶点，从全景观察药物作用机制；网络药理学（系统层）是组学策略的核心应用之一，向上可扩展转录组学、蛋白质组学、代谢组学等真实测量数据层。**

定位演进分三步，且每一步都必须显式决策，不默认跨越：

1. **现状**：面向 AD 的窄领域网络药理学平台（ADR-0017 契约基线）。
2. **本次方向**：以组学策略为底层逻辑的网络药理学平台（本 ADR）。
3. **未来方向**：整个组学研究辅助平台（只作为远期拓展方向，不在本 ADR 中立项或实现）。

“升级”改变的是平台的解释框架与扩展路线，不是立即改变病种范围、默认运行路径或产品文案。

### 2. 分层模型

平台按四层组织，provenance 与可复算要求纵贯四层：

| 层 | 职责 | 当前事实（2026-08-15） | 门禁 |
|---|---|---|---|
| 数据层 | 研究协议、文献/古籍、方药-成分-靶点-通路知识数据，以及转录组/蛋白质组/代谢组等真实测量数据 | JSON seed + runtime、PubMed opt-in、Open Targets / ChEMBL 离线 raw artifact 已落地；真实组学数据通道不存在 | 任何 raw artifact 必须走 provenance 门禁；客户端不得声明 records/hash/provenance/readiness |
| 分析层 | 把数据转化为可复算分析：网络药理学系统层分析为核心；分子对接/分子动力学为计算验证方向；组学差异分析、通路分析与多组学整合为未来扩展 | 网络药理学默认 mock、live opt-in；GO/KEGG 富集为本地模拟；对接/MD 仅 schema 预留 | 只允许在封存快照上分析；mock 与 live 必须显式标注；不因分层升级提前引入重依赖 |
| 验证层 | 区分“产物一致”与“科学成立”：独立复算、逐边证据核验、人工判定、真实测量数据验证 | `artifact_consistency_pass` 与 `scientific_readiness` 已分开；adjudication 与候选装配计划已落地但无真人判定；组学测量验证不存在 | `formal_network_ready` 在科学验证完成前恒为 `false`；数据库预测不得标为实验证据 |
| 报告层 | 输出研究协议、lineage、来源边界、证据分级、阻塞项、免责声明与可复核材料 | 网络 Markdown 报告已可导出，并展示证据分级与装配门禁 | 报告只陈述已通过的门禁；不把方向规划写成既有能力 |

### 3. 网络药理学是系统层核心

网络药理学仍是第一产品主轴和当前唯一实现主线。它在组学策略中承担“系统层”角色：把复方-成分-靶点-通路-疾病作为一个整体系统来建模和核验，而不是预先锁定单一靶点。

- 当前 AD 窄领域、`Homo sapiens`、研究协议门禁、逐边 lineage 与 ADR-0017 全部科研门禁保持不变。
- 组学策略不替换网络药理学，也不把转录组/蛋白组/代谢组分析提前变成并列产品。
- 真实组学数据未来进入平台时，必须先回答“它验证或修正了网络中的哪条边/哪个层级”，而不是另起一个互不相干的分析模块。

### 4. 真实组学数据 opt-in，不破坏默认离线纪律

真实组学数据是显式 opt-in 的验证层输入，不进入默认路径：

- 默认仍不采集、不上传、不外发任何组学数据。
- 任何组学原始文件、表达矩阵、注释或临床元数据都必须先通过 provenance 门禁，才能被分析层或验证层消费。
- 接入真实组学数据不意味着自动获得“真实证据验证通过”结论；还必须通过实验设计、质控、批次/归一化、统计方法与领域复核等科学门禁。
- 默认不接真实 LLM、真实 embedding、生产数据库、Neo4j、Celery、Redis、MinIO 或外部生产服务；组学数据接入不成为绕过这些纪律的理由。

## 北极星案例：夏枯草干预甲状腺疾病的整合研究

以研究者本人夏枯草干预甲状腺疾病整合研究为平台验证案例，路径为：

> 古籍数据挖掘 → 网络药理学 → 分子对接 → 分子动力学

该研究四步完整跑通、可复算，是“从知识到计算到验证”的完整研究路径样本。平台应能逐步支撑这类路径，并最终接入真实组学数据做验证。

本 ADR 对北极星案例设定三条边界：

1. **研究本身不改动**：平台不修改、不重做、不冒用该研究结论，也不在未获授权时复制其数据。
2. **平台先按现有样子跑通基础流程**：先以当前 AD 范围、默认 mock 或已核验离线 raw artifact 跑通“定研究协议 → 构建方药-成分-靶点-通路网络 → 核验逐边证据 → 运行富集 → 导出报告”，并生成可复算证据包；不因此立即加入甲状腺病种。
3. **四步路径只作能力蓝图**：把古籍数据挖掘、网络药理学、分子对接、分子动力学映射为平台当前能力/差距矩阵；分子对接与分子动力学仍维持 schema 预留，不得宣称已有功能。

## 与 ADR-0017 的关系

- **ADR-0017 保留为当前契约基线**：实现、测试、默认配置与产品范围仍以 0017 为准；本 ADR 不修改、不取代 0017。
- **ADR-0018 是方向演进层**：0017 回答“现在只做什么产品”，0018 回答“这个产品底层依据什么科研逻辑、未来向哪里扩展”。
- **冲突时以 0017 为准**：在 0018 转 Accepted 且相关边界通过新 ADR 修订之前，任何“组学策略”解释都不得放宽 0017 的约束。
- **明确对齐**：
  - 网络药理学仍是唯一产品主轴；文献/PDF/RAG 仍是证据服务层。
  - 研究协议、明确表型、`Homo sapiens`、证据策略、查询日期门禁不变。
  - `artifact_consistency_pass` 与 `scientific_readiness` 分开报告不变。
  - mock 默认、live 显式 opt-in、`formal_network_ready` 失败关闭不变。
- **明确修订边界**：以下任何变化都必须通过新的 ADR 或对 0017 的显式修订，不得由本草案隐含授权：
  - 病种超出特应性皮炎（例如把甲状腺疾病纳入产品范围）；
  - 物种超出 `Homo sapiens`；
  - 把分子对接/MD 从 schema 预留提升为实际功能；
  - 把组学分析变成与网络药理学平行的默认产品；
  - 翻转任何默认离线/不外发纪律或 `formal_network_ready`。

## 边界与不变量

延续既有纪律：

1. **默认不外发数据**：外部 provider 只作本地显式 smoke；受控外发继续遵守 ADR-0011 / ADR-0012 的既有边界。
2. **默认不接真实 LLM / embedding**：默认路径保持 deterministic + keyword；真实能力只能显式 opt-in。
3. **可复算**：稳定 hash、不可变快照、独立 validator、同输入同输出；runtime 状态不回写 seed。
4. **诚实标注**：mock 恒为 `mock_inferred`；seed 样本、live 记录、predicted/experimental 证据等级必须分开展示；不把方向规划写成既有能力。
5. **不冒充真实证据**：数据库预测不是实验证据；有 provenance 的预测仍是预测；有组学文件也不等于已验证。

新增不变量：

6. **组学数据 provenance 门禁**：任何组学数据接入必须走与现有 Open Targets / ChEMBL raw-artifact 同级的门禁——operator-controlled trusted manifest、服务端 raw-byte SHA-256、不可变 raw artifact 快照、静态 parser provenance、lineage、协议绑定与独立复算。客户端不得提交 records/hash/provenance/readiness/判定字段；未过门禁的组学数据必须失败关闭或标记为未验证，不得借“组学”名义进入验证层。
7. **组学数据最小元数据**：在消费任何组学数据前，manifest 至少绑定数据身份、物种/组织/条件、样本分组、检测平台与版本、质控与批次/归一化信息、统计方法、数据使用授权/许可与获取时间；缺失关键元数据时不得进入分析层。
8. **组学验证不绕过人工判定**：组学证据是新证据类型，必须进入逐行 lineage、证据分级与 HITL 判定；不得用“组学策略”四个字替代 reviewer 判定或翻转 readiness。
9. **不提前重依赖**：不因“组学平台”方向立即引入工作流引擎、云计算组学平台、GPU 重计算、图数据库或生产级多组学存储。

## 里程碑（仅方向规划，不实现代码）

本 ADR 本身不批准任何代码改动。每个 Gate 都需要单独计划、契约与验收；通过当前门禁的 TDD/独立 validator 纪律继续适用。

- **Gate 1 方向确认（已完成 2026-08-16）**：研究者已确认"组学策略"定义、四层模型、北极星案例映射与 0017 边界。确认记录见 [0018-gate1-confirmation-record.md](0018-gate1-confirmation-record.md)；0018 已转 Accepted。未写代码、未改 README 产品边界。
- **Gate 2 北极星案例跑通基础流程（已完成 2026-08-15）**：已在现有 AD 平台按"定协议 → 建网络 → 核证据 → 富集 → 报告"跑通可复算基础流程（mock 模式，消风散→5 条链路→14 个富集项），并产出夏枯草四步路径的能力/差距/前置门禁矩阵。证据包见 [0018-gate2-evidence-summary.md](0018-gate2-evidence-summary.md)，能力矩阵见 [0018-gate2-capability-gap-matrix.md](0018-gate2-capability-gap-matrix.md)。复现验证通过（chains/enrichment terms/lineage/readiness 全部一致）。未新增甲状腺病种、未实现对接/MD、未接组学数据，`formal_network_ready` 保持 `false`。
- **Gate 3 组学数据验证层（已完成 2026-08-15）**：已选定转录组（Transcriptomics）模态与 GSE32924 数据集（33 例人类 AD 皮肤活检，GEO open access），定义最小元数据与 manifest 契约，提出 `omics_validated` 新证据等级（6 项升级条件，「有文件即 experimental」被禁止）。Gate 3 只覆盖 disease target verification（靶点→疾病边），compound target verification 留后续。评估详情见 [0018-gate3-evaluation.md](0018-gate3-evaluation.md)。默认路径仍不接组学数据，`formal_network_ready` 保持 `false`，未写代码。

## 风险与开放问题

| 风险 | 缓解 |
|---|---|
| 只有“组学策略”之名，没有真实测量数据之实 | 任何文档、UI 与报告都不得把本 ADR 的方向描述为已有能力；Gate 3 前不出现组学验证成功话术 |
| 北极星案例被过早当成产品需求 | 甲状腺病种、对接/MD 功能必须走独立 ADR/修订门禁；Gate 2 只跑现有 AD 基础流程与差距映射 |
| 组学数据涉及隐私、伦理与授权 | 默认本地、不外发；数据集进入 manifest 前必须确认许可/伦理/授权；遵守既有 PIPL 边界 |
| 用方向升级掩盖当前网络药理学未闭环 | 继续承认 `formal_network_ready=false`、检索指标为 null、无真人判定；0017 主线仍是唯一工程主线 |
| 范围蔓延到多组学平台 | 只把“整个组学研究辅助平台”列为远期方向；每个新模态都必须单独立项 |

## 后果

- 平台讨论与规划采用“组学策略 / 四层模型 / 北极星案例”作为共享语言；当前事实源不因此改变。
- ADR-0017 继续作为实现与验收基线；本 ADR 转 Accepted 前，README、AGENTS、CONTEXT 的产品边界文案不作实质变更。
- 默认路径、API 契约、测试与离线纪律不变；本 ADR 不触发任何网络、组学、对接/MD 代码实现。
- `formal_network_ready` 仍为 `false`；本 ADR 不代表科学就绪，不代表已接入任何真实组学数据。
