# ADR-0016: RAG 引用的透明检索匹配度（替换常量置信度语义）

日期：2026-07-04

## 状态

Accepted

## 背景

对外路演宣称「AI 预测驱动、定量药效排序」。用第一性原理核对代码后确认：RAG 引用卡片上显示的「置信度」来自 `CONFIDENCE_BY_SOURCE_TYPE` **常量**（`cn_literature=0.86` / `pubmed=0.74`），只取决于来源类型，与该条引用和具体问题的实际相关度无关。把一个固定常量叫「置信度」并按百分比展示，会让医生/科研 reviewer 误以为那是模型对答案正确性或疗效的定量判断——这正是幻灯片「定量药效排序」措辞的假精度风险。

同时发现：**真实的相关度信号本就存在**——引用是按检索候选的真实得分 `ScoredCandidate.score` 排序后选出的，只是这个真实分数从未暴露给用户，展示层反而用了常量。

## 决策

1. **暴露真实、可计算的 `match_score`（检索匹配度）**：在引用装配处按「本次结果集内最高检索得分」归一，`match_score = round(candidate.score / max_selected_score, 4)`，top 命中饱和到 `1.0`。纯确定性，来自既有 keyword ranker，不引入模型、不外发。

2. **诚实标注，明确不是概率/疗效**：`match_score` 是「按检索得分归一的相对相关度启发式」，导出与前端文案显式声明「非概率、非疗效或置信判断」。

3. **常量降格但保留**：`confidence` 字段保留（向后兼容，约 20 处测试构造 `CitationCard(confidence=…)`、prompt 与 grounding 仍用它），但展示语义从「置信度」改为「**来源类型先验**」，如实说明它只是按来源类型的固定基线权重。

4. **不新增排序逻辑**：本切片只暴露与诚实标注已有信号，不改变 citation 选择或排序，不宣称「药效」。真正的定量药效/概率排序需要真实模型与验证，属未来独立切片，不在此借鉴范围。

## 后果

正面：
- 幻灯片「定量排序」措辞落成诚实版本：展示真实检索相关度，而非把常量伪装成置信度。
- 用户能看到「这条引用相对本次检索有多相关」，且明确知道它不是疗效/概率。
- 零新增重依赖，纯确定性，默认路径生效。

代价：
- `match_score` 是检索相关度代理，不是答案正确性或临床疗效度量；命名与文案已强调此边界。
- `confidence` 常量仍在 payload 中（向后兼容），需靠「来源类型先验」标签避免再被误读。
