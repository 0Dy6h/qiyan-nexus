# Celery + Redis 异步任务架构

网络药理学分析等耗时操作使用 Celery + Redis 异步任务队列处理，用户通过 `task_id` 轮询进度和结果。

## 方案

- **任务队列**：Celery（Python 异步任务队列）
- **消息代理**：Redis（同时用于语义缓存和任务队列）
- **监控**：Flower（端口 5555，Celery 任务监控面板）
- **用户交互**：提交分析 → 返回 task_id → 前端轮询 `/result/{task_id}` → 完成后展示报告

## 为什么不用同步处理

网络药理学分析流程（草药→成分→靶点→PPI→GO/KEGG）涉及多个计算步骤和外部 API 调用，耗时通常在 30 秒至数分钟。同步 HTTP 请求会导致：
1. 浏览器超时
2. 用户无反馈地等待
3. 服务器连接占用

## 为什么用 Celery 而非更轻量的方案

1. **成熟度**：Python 生态最成熟的异步任务框架，文档和社区完善
2. **监控**：Flower 面板开箱即用，适合内测阶段观察任务状态
3. **复用以有的 Redis**：不引入额外的消息代理
4. **扩展性**：阶段 2 可平滑升级到多 worker、任务优先级、定时任务
