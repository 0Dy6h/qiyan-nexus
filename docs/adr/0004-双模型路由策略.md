# 双模型路由策略：DeepSeek V4 Flash + Claude Sonnet 4.6

> **状态：历史规划提案，已被当前 provider 策略取代。** 默认 deterministic，live provider 仅显式 opt-in；不要执行本文旧模型名或旧 endpoint。

LLM 路由采用硬编码规则：按 API endpoint 决定使用哪个模型。不引入额外的分类 LLM，降低延迟和成本。

## 路由规则

| API Endpoint | 模型 | 理由 |
|---|---|---|
| `/rag/query` | DeepSeek V4 Flash | 检索增强问答，成本优先，推理深度要求适中 |
| `/netpharm/report` | Claude Sonnet 4.6 | 结构化长报告，需要高质量医学推理 |
| `/syndrome/*`（阶段 2） | Claude Sonnet 4.6 | 辨证辅助，临床决策敏感 |

## 模型访问

- **DeepSeek V4 Flash**：通过 DeepSeek 官网 API
- **Claude Sonnet 4.6**：通过 opencode zen API 调用

## Fallback

Claude Sonnet 4.6 日配额用尽时，所有请求 fallback 到 DeepSeek V4 Flash。免责声明「非诊断结论、需结合临床」覆盖所有模型输出，与路由选择无关。

## Considered Options

1. **全用 DeepSeek** — 成本最低，但医学推理质量不足，尤其网络药理学报告
2. **全用 Claude** — 质量最高，但成本高且 API 依赖单一
3. **硬编码路由（选定）** — 在成本和质量的交界面上做划分，简单可预测
