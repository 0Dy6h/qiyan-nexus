# ADR-0015: 前端 UI 栈迁移至 shadcn/ui

日期：2026-06-10

## 状态

Accepted

## 背景

Qiyan Nexus 当前前端栈为 Next.js 16 + React 19 + Ant Design 6（ADR-0009）。产品定位是面向医生/科研人员的特应性皮炎证据工作台——专业、可信、高信息密度、证据优先。

在实际页面打磨过程中发现：
- Ant Design 的默认气质偏向通用企业后台，品牌辨识度较弱。
- 要在 Ant Design 基础上做出克制、现代、细腻的医疗科研产品感需要大量覆盖样式。
- shadcn/ui + Tailwind + Radix 的视觉上限更高，组件可定制性更强，更容易打磨出目标气质。

## 决策

1. **目标栈**：shadcn/ui + Tailwind CSS + Radix UI + Next.js 16 + React 19。
2. **迁移策略**：
   - **分阶段进行**：先建立设计系统规范，再选核心页面试点，最后按优先级逐页迁移。
   - **不做一次性全量重写**：Ant Design 作为过渡期遗留栈，新页面优先 shadcn/ui，老页面按需重构。
   - **试点先行**：选一个核心页面（建议 `/literature` 或 `/rag`）完整迁移并验证设计系统可行性。
3. **视觉原则**：
   - 专业、可信、浅色、低噪音、中高信息密度、证据优先。
   - 保留青黛绿主色：`#0d9488` / `#14b8a6`。
   - 避免花哨 AI 风、玻璃拟态、大面积渐变、营销页式 hero。
4. **技术约束**：
   - 保持 Next.js 16 + React 19 不变。
   - Tailwind 与现有 CSS 样式共存，逐步过渡。
   - shadcn/ui 组件按需安装到 `components/ui/`，不引入完整 UI 框架包。

## 后果

**正面**：
- 更高的视觉定制上限，更容易打磨产品气质。
- 组件源码可见可控（shadcn/ui 是 copy-paste 模式），便于调整细节。
- Tailwind 的原子化样式与信息密度场景契合度高。
- Radix UI 提供无障碍基础，符合医疗产品要求。

**代价**：
- 需要建立新的设计系统规范（颜色、间距、排版、组件）。
- 过渡期会有 Ant Design 和 shadcn/ui 两套组件共存，需维护一致性。
- 团队需熟悉 Tailwind 开发模式（如未使用过）。
- 迁移工作量按页面数线性增长，需排期。

**风险缓解**：
- 试点页面验证设计系统可行性后再全面推进。
- 保留 ADR-0009 中 Ant Design 作为后备方案，关键场景（如表单、表格）可继续使用成熟组件。
- 建立设计 token 文档（`docs/design-system.md`）统一管理视觉规范。

## 验证

迁移验证标准：
1. 试点页面通过 `pnpm build` 和 `pnpm typecheck`。
2. 视觉效果符合"专业、可信、低噪音"定位，信息层级清晰。
3. 无障碍测试通过（键盘导航、ARIA 标注）。
4. 核心交互（文献列表、RAG 答案展示）完整可用。
