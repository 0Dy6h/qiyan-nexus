## 确认项一：「组学策略」定义

**命题**：平台底层逻辑定义为「组学策略（Omics Strategy）」，即：

> 系统整体观：不预设单一靶点，从全景观察药物作用机制；网络药理学（系统层）是组学策略的核心应用之一，向上可扩展转录组学、蛋白质组学、代谢组学等真实测量数据层。

**定位演进（三步，每步须显式决策）**：
1. 现状：面向 AD 的窄领域网络药理学平台（ADR-0017 契约基线）
2. 本次方向：以组学策略为底层逻辑的网络药理学平台（本 ADR）
3. 未来方向：整个组学研究辅助平台（远期拓展方向，不在本 ADR 中立项或实现）

**关键约束**：「升级」改变的是平台的解释框架与扩展路线，不立即改变病种范围、默认运行路径或产品文案。

**ADR-0018 引用**：§决策.1（组学策略作为底层逻辑）

确认结果：☑ 认可　　2026-08-16 研究者本人确认通过

## 确认项二：四层模型

**命题**：平台按四层组织，provenance 与可复算要求纵贯四层：

| 层 | 职责 | 当前事实（2026-08-15） | 门禁 |
|---|---|---|---|
| **数据层** | 研究协议、文献/古籍、方药-成分-靶点-通路知识数据，以及转录组/蛋白质组/代谢组等真实测量数据 | JSON seed + runtime、PubMed opt-in、Open Targets / ChEMBL 离线 raw artifact 已落地；真实组学数据通道不存在 | raw artifact 必须走 provenance 门禁；客户端不得声明 records/hash/provenance/readiness |
| **分析层** | 把数据转化为可复算分析：网络药理学系统层分析为核心；分子对接/分子动力学为计算验证方向；组学差异分析、通路分析与多组学整合为未来扩展 | 网络药理学默认 mock、live opt-in；GO/KEGG 富集为本地模拟；对接/MD 仅 schema 预留 | 只允许在封存快照上分析；mock 与 live 必须显式标注；不因分层升级提前引入重依赖 |
| **验证层** | 区分「产物一致」与「科学成立」：独立复算、逐边证据核验、人工判定、真实测量数据验证 | `artifact_consistency_pass` 与 `scientific_readiness` 已分开；adjudication 与候选装配计划已落地但无真人判定；组学测量验证不存在 | `formal_network_ready` 在科学验证完成前恒为 `false`；数据库预测不得标为实验证据 |
| **报告层** | 输出研究协议、lineage、来源边界、证据分级、阻塞项、免责声明与可复核材料 | 网络 Markdown 报告已可导出，并展示证据分级与装配门禁 | 报告只陈述已通过的门禁；不把方向规划写成既有能力 |

**关键约束**：
- 网络药理学仍是第一产品主轴和当前唯一实现主线，在组学策略中承担「系统层」角色。
- 真实组学数据未来进入平台时，必须先回答「它验证或修正了网络中的哪条边/哪个层级」，而不是另起一个互不相干的分析模块。

**ADR-0018 引用**：§决策.2（分层模型）、§决策.3（网络药理学是系统层核心）

确认结果：☑ 认可　　2026-08-16 研究者本人确认通过

## 确认项三：北极星案例映射

**命题**：以研究者本人夏枯草干预甲状腺疾病整合研究为平台验证案例，路径为：

> 古籍数据挖掘 → 网络药理学 → 分子对接 → 分子动力学

该研究四步完整跑通、可复算，是「从知识到计算到验证」的完整研究路径样本。

**三条边界**：
1. **研究本身不改动**：平台不修改、不重做、不冒用该研究结论，也不在未获授权时复制其数据。
2. **平台先按现有样子跑通基础流程**：先以当前 AD 范围、默认 mock 或已核验离线 raw artifact 跑通「定研究协议 → 构建方药-成分-靶点-通路网络 → 核验逐边证据 → 运行富集 → 导出报告」，并生成可复算证据包；不因此立即加入甲状腺病种。
3. **四步路径只作能力蓝图**：把古籍数据挖掘、网络药理学、分子对接、分子动力学映射为平台当前能力/差距矩阵；分子对接与分子动力学仍维持 schema 预留，不得宣称已有功能。

**能力/差距初步映射**（Gate 2 将细化）：

| 研究步骤 | 平台当前能力 | 差距 | 前置门禁 |
|---|---|---|---|
| 古籍数据挖掘 | 文献/PDF/RAG 证据服务层可支持文本检索与引用 | 缺乏古籍专项数据源与结构化挖掘工具 | 证据服务层按网络研究对象绑定（ADR-0017） |
| 网络药理学 | mock 默认、live opt-in；双侧 raw-artifact provenance、lineage、adjudication、assembly gate 均已落地 | 无真人判定记录；`formal_network_ready=false`；检索指标为 null | 真人 reviewer sign-off；Track A 标注 |
| 分子对接 | schema 预留（`protein`、`ligand` 等） | 无 router/service/repository，无真实计算 | 独立 ADR 立项 |
| 分子动力学 | schema 预留（`simulation_task` 等） | 无 router/service/repository，无真实计算 | 独立 ADR 立项 |

**ADR-0018 引用**：§北极星案例（三条边界）、§决策.4（真实组学数据 opt-in）

确认结果：☑ 认可　　2026-08-16 研究者本人确认通过

## 确认项四：与 ADR-0017 的边界对齐

**命题**：ADR-0017 保留为当前契约基线，ADR-0018 是方向演进层，冲突时以 0017 为准。

**明确对齐项**（0018 不改变以下内容）：
- 网络药理学仍是唯一产品主轴；文献/PDF/RAG 仍是证据服务层
- 研究协议、明确表型、`Homo sapiens`、证据策略、查询日期门禁不变
- `artifact_consistency_pass` 与 `scientific_readiness` 分开报告不变
- mock 默认、live 显式 opt-in、`formal_network_ready` 失败关闭不变

**明确修订边界**（以下变化必须通过新 ADR 或对 0017 显式修订，不由本草案隐含授权）：
- 病种超出特应性皮炎（如把甲状腺疾病纳入产品范围）
- 物种超出 `Homo sapiens`
- 把分子对接/MD 从 schema 预留提升为实际功能
- 把组学分析变成与网络药理学平行的默认产品
- 翻转任何默认离线/不外发纪律或 `formal_network_ready`

**当前事实诚实承认**：
- `formal_network_ready` 仍为 `false`，不应以任何方式宣称科学就绪
- 检索质量指标 `precision@5` / `MRR@5` 仍为 `null`，150 个 Track A 人工标签尚未填写
- 人工 adjudication 工程能力已上线，但尚无任何真实领域 reviewer 判定记录
- 网络药理学默认仍是 mock 演示链路
- 本质短板不是「工程 provenance 不够」，而是平台目前主要是数据库预测工具，缺真实测量数据验证

**ADR-0018 引用**：§与 ADR-0017 的关系、§边界与不变量

确认结果：☑ 认可　　2026-08-16 研究者本人确认通过

## 本确认不授权的事项（边界红线）

根据飞书任务「岐研枢方向推进（ADR-0018 Gate 1）」明确指示：

1. **不写代码**：Gate 1 是方向确认，不触发任何代码实现
2. **不改病种/物种边界**：仍为特应性皮炎 + `Homo sapiens`
3. **`formal_network_ready` 仍为 `false`**：本确认不代表科学就绪
4. **不接真实组学数据**：组学数据通道不存在，Gate 3 前不接入
5. **不实现对接/MD**：分子对接与分子动力学维持 schema 预留
6. **不改 README/AGENTS/CONTEXT 产品边界文案**：0018 转 Accepted 前，产品边界文案不作实质变更
7. **不提前引入重依赖**：不因「组学平台」方向立即引入工作流引擎、云计算组学平台、GPU 重计算、图数据库或生产级多组学存储

## 开放问题（记录但不阻塞 Gate 1）

以下问题留待后续 Gate 处理，Gate 1 不要求解答：

1. 首个组学验证层应选转录组、蛋白质组还是代谢组？使用哪一份已授权数据？
2. 组学数据的最小 manifest/元数据标准由谁定义、如何与 raw-artifact 纪律统一？
3. 组学测量证据如何映射到 ADR-0015 的 `experimental` 证据等级，避免「有文件即 experimental」？
4. 北极星案例中的古籍数据挖掘是否应成为证据服务层的专项能力，还是仅作为方法学参照？
5. 分子对接/分子动力学最终是平台内功能，还是保持外部工具链 + 报告导入的边界？
6. 真实 reviewer 判定与 Track A 标注由谁完成、何时完成，如何与本方向 Gate 排序？
