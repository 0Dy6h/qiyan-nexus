# NextAuth.js 魔法链接 + 邀请白名单认证

> **状态：Deferred historical proposal。** 当前未采用 NextAuth；内部预览访问边界以 `docs/current-state.md` 和 cloud trial runbook 为准。

采用 NextAuth.js（Auth.js v5）实现无密码认证：用户通过邮箱接收一次性魔法链接登录，注册受邀请白名单控制。

## 方案

- **框架**：NextAuth.js v5（与 Next.js 15 原生集成）
- **登录方式**：邮件魔法链接（Magic Link），无密码
- **注册控制**：管理员维护邀请白名单，只有白名单邮箱可通过魔法链接登录
- **邮件发送**：通过 SMTP 服务（如 Resend、SendGrid）发送一次性登录链接

## 为什么不用密码

1. **安全简化**：无需存储和哈希密码，消除密码泄露风险
2. **合规简化**：减少需要保护的敏感数据类别（PIPL 合规时少一个维度）
3. **用户体验**：50 人内测的医生群体，查邮箱流程自然，无需记忆额外密码
4. **实现简单**：NextAuth.js 内置 Magic Link provider，配置量远小于密码方案

## 为什么需要邀请白名单

医疗平台涉及临床辅助决策，需要对用户身份有基本把控。内测阶段 50 人规模下，手动维护白名单成本极低，且避免了公开注册带来的合规和滥用风险。
