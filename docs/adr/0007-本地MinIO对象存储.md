# 对象存储：本地 MinIO（而非 Cloudflare R2）

MVP 阶段使用 Docker Compose 自建 MinIO 作为 PDF 文件对象存储，替代 Cloudflare R2。

## 为什么选 MinIO 而非 R2

1. **零外部依赖**：MinIO 作为 Docker Compose 服务容器内运行，不依赖外部云服务账号
2. **零额外成本**：Cloudflare R2 有存储和流量费用，MVP ¥960 预算下可完全避免
3. **开发体验**：本地开发无需网络，无跨区域延迟，调试更方便
4. **迁移路径保留**：MinIO 和 R2 都是 S3 API 兼容，阶段 2 如需迁移到 R2，只需改 endpoint 配置，代码零改动

## 为什么不用本地卷挂载

本地文件系统挂载虽然更简单，但：
1. 文件路径依赖宿主机，多容器共享困难
2. 与云部署（阶段 2）的存储模型不兼容
3. 缺乏权限控制、版本管理、生命周期策略

MinIO 提供 S3 兼容接口，代码层面与未来任何 S3 兼容存储（R2、AWS S3、阿里云 OSS）无差异。
