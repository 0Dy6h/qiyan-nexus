# ADR-0017：网络药理学主轴与证据服务层产品契约

- 状态：Accepted
- 日期：2026-07-11
- 决策者：项目所有者

## 背景

仓库在 MVP-A 期间成功完成文献、PDF、RAG、引用、导出、检索评估、LLM grounding 与预览安全建设，但这些能力逐渐成为事实上的产品主轴；网络药理学仍停留在 `query + analysis_type` 的 mock 任务壳。该方向无法满足“窄向垂直领域网络药理学自动化科研辅助平台，附带文献检索与临床证据服务”的原始目标。

## 决策

Qiyan Nexus 的唯一产品主轴改为：

> 面向特应性皮炎中医药研究的窄领域网络药理学自动化科研辅助平台。

文献检索、PDF 归档、证据问答、引用核验与导出属于证据服务层，必须逐步绑定到研究项目、靶点、通路、网络边或科研 claim；它们不再作为与网络药理学平行的第一产品。

## 强制科研门禁

任何新网络任务必须先冻结最小研究协议：

- 疾病范围：仅特应性皮炎；
- 明确表型：禁止仅用宽泛 disease target union；
- 物种：当前仅 `Homo sapiens`；
- 证据策略：直接人类证据优先或显式混合探索；
- 查询日期；
- 后续真实模式必须补齐数据库版本、score/threshold、标识符映射和人工判定。

系统必须分别报告：

- `artifact_consistency_pass`：文件、参数、关系、统计和导出是否内部一致；
- `scientific_readiness`：证据是否足以支持目标科研结论。

默认 mock 任务、缺少外部来源版本或缺少逐边人工判定的任务，`formal_network_ready` 必须为 false。

## 工程优先级

1. 研究协议、项目对象、来源 lineage 与 readiness gate；
2. 小规模真实 compound-target-pathway 可复核闭环；
3. 文献/RAG 与研究对象绑定；
4. 独立复算与报告一致性；
5. 经过上述门禁后，再评估扩大语料、LLM、embedding、图数据库、任务队列或分子模拟。

真实检索 Track A 标注仍有价值，但属于证据服务层质量验证，不再占用唯一工程主线；应由独立真人 reviewer 以 HITL 方式继续。

## 后果

- 首页、导航和网络页面将网络药理学置于第一入口。
- `/api/network/analyze` 请求新增必填研究协议；旧客户端必须升级。
- legacy task 可读取但协议为空，科研 readiness 失败关闭。
- 既有 RAG、PDF、检索与安全能力保留，不删除；暂停无主研究链路牵引的继续扩张。
- 默认依赖边界不变：不因方向纠偏而立即引入 Neo4j、Celery、真实 LLM 或其他重依赖。
