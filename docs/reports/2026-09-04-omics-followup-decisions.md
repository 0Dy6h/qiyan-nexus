# 2026-09-04 决策记录：omics 遗留两项的对抗性审查结论

> 研究者本人授权：「不用我排版，你来对抗性审查决定即可」。
> 本记录把两项遗留候选的反对意见摆在明面上，结论均为**不实施**，并给出未来立项的前置条件。

## D1：是否为 IL6/STAT3/TNF 冻结 AL vs ANL 第二对比 snapshot？——**否**

### 对抗性审查

1. **outcome-shopping 风险**：v1 预登记对比是 AL vs Normal（计划 §一原文）；拿到阴性结果后改用另一对比，即使有文献动机（Suárez-Fariñas 2011 的核心设计确实是配对 AL vs ANL），正确做法也是预登记新对比框架，而不是事后替换。事后换对比 = 按想要的结果挑口径，正是本项目门禁纪律要防的事。
2. **统计设计不匹配（本次探针新增的硬证据）**：AL/ANL 是 12 例患者的配对样本。在冻结管线（series matrix log2 values + 非配对 Welch + 基因层面 BH）下对真实冻结数据探针：
   - 21,755 基因中 |log2FC|>1 有 566 个，但 **adj_p<0.05 = 0 个**，两者交集为空；
   - IL6 adj_p=0.72 (+0.16)、STAT3 adj_p=0.44 (+0.21)、TNF adj_p=0.42 (+0.24)，全部不通过。
   - 个体间表达差异完全淹没组间对比——原文献结论建立在**配对统计 + RMA 归一化**上。有效的 AL vs ANL 分析必须换统计设计（配对检验，或 D-G3-A(b) 的 R/limma 路线），这是 ADR-0018 L94-99 管线契约级变更，不是参数调整。
3. **契约变更成本**：不可变快照按 accession 封存，第二对比需要把快照键扩展为 accession+analysis_context hash（schema 与 validator 契约变更）。
4. **无正收益动机**：即使立刻做，当前管线下该对比也是空集，三个目标照样拿不到候选。

### 结论与前置条件（全部满足才可立项）

- [ ] 管线支持配对统计设计（新 ADR，属 ADR-0018 L94-99 修订边界）
- [ ] 快照键扩展契约（accession + analysis_context）设计与 validator 同步
- [ ] 预登记决策包：对比定义、验证目标、阈值，先拍板后跑数

**诚实边界**：v1 验证目标（IL6/STAT3/TNF）在两个对比下、当前确定性管线口径下，均未获得 `omics_validated` 候选。探针为非权威工程侧复算（.tmp 脚本），冻结快照未做任何改动。

## D2：是否给 `/network` 增加 omics opt-in UI 入口？——**否（现阶段）**

### 对抗性审查

1. **默认路径纪律**：ADR-0018 把组学定义为显式 opt-in 验证层；UI 入口天然把组学拉向默认用户路径——评审者会把看到的按钮当成主流程的一部分，违背「不进默认路径」的不变量。
2. **瓶颈错位**：HITL 流的真实瓶颈是**至今没有任何真人 domain reviewer**，不是没有按钮。给空的 append-only 审计流做 UI 是本末倒置；判定者（受信 nginx 后的 reviewer）当前以 API/操作员方式工作是足够且更克制的。
3. **工程量错位**：可用的 omics UI 是一个纵向切片（accession 输入 + manifest 上传 + DEG 投影表 + 带护栏提示的判定按钮 + 快照/候选状态展示），不该在收尾阶段顺手做半成品。
4. **操作员前置**：omics 快照的建立依赖操作员在产品外完成（GEO 下载、manifest 编写、封存导入）。UI 之前先有稳定的操作员 runbook 更有价值。

### 结论

保持 **API-only**。UI 作为未来独立切片候选（触发条件：有真实冻结快照工作流 + 首位真人 reviewer 在场 + 研究者批准切片计划）。已同步写入 `docs/current-state.md` 下一步候选。
